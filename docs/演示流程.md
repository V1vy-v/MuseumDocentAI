# 演示流程（答辩 / 课堂展示用）

> 目标：用最短时间把"已经做出来的东西"讲清楚、跑起来、看到效果。
> 全流程约 8 分钟，可按需裁剪到 5 分钟。

---

## 〇、演示前 5 分钟检查（别在台上做）

| 检查项 | 命令 / 操作 | 通过标准 |
|---|---|---|
| 后端启动 | `cd backend` → `.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000` | 日志出现 `[向量库] 就绪 dim=1024 ...` |
| 索引就绪 | 浏览器打开 `http://127.0.0.1:8000/api/health` | `"ready": true, "dim": 1024` |
| 手机联网 | 手机与电脑同一 WiFi | 手机浏览器打开 `http://<电脑IP>:8000/api/health` 能看到 JSON |
| APP 地址 | 左上角 ☰ 抽屉 → 底部「服务器」 | 填 `http://<电脑IP>:8000` 并保存 |
| 播报开关 | 右上角 🔊 按钮 | 演示语音时打开，演示"纯文字"时关闭 |
| 调试台备用 | 浏览器打开 `http://127.0.0.1:8000/debug` | 能发消息（真机出问题时用它兜场） |

## 一、开场（30 秒）：一句话讲清项目

> "这是一个博物馆讲解助手：安卓端负责语音交互，后端用 RAG（检索增强生成）保证回答基于资料、不瞎编。
> 资料库收录了 **616 份**国内一级博物馆与其馆藏文物的公开资料。"

---

## 二、主演示：文字问答（2 分钟）

**操作**：APP 输入框输入 → 发送

| 顺序 | 输入 | 预期效果 | 讲解要点 |
|---|---|---|---|
| 1 | `越王勾践剑是什么时期的文物？` | 回答"春秋晚期…1965 年出土…藏于湖北省博物馆"，**下方显示来源：越王勾践剑** | "答案不是模型凭记忆编的，是从资料库里检索出来的，来源可以点开看原文" |
| 2 | `它在哪个城市？` | 正确答"武汉" | **多轮指代消解**：把"它"还原成上一轮的"越王勾践剑" |
| 3 | `湖北省博物馆开放时间是几点？` | 明确回答"资料里没有收录，建议看馆方官方渠道" | **防幻觉**：知识库没有的信息绝不编造（早期版本会编"周二到周日九点到五点"） |
| 4 | `附近有什么好吃的？` | 兜底话术，**无来源** | 与博物馆无关的问题不乱答；来源为空说明检索闸门生效 |

## 三、语音演示（2 分钟）

**操作**：点右下「语音」→ 允许麦克风 → 说一句话 → 再点「停止」

| 观察点 | 说明 |
|---|---|
| 用户气泡显示 `🎤 识别出的问题` | **本次新增**：以前只显示"语音提问"，看不到自己说了什么 |
| 回答自动朗读 | 语音播报开关打开时，回答文字 + 语音一起给出 |
| 开关关闭再问一次 | 只有文字、**完全没有声音** |
| 播报中点「语音」 | 立刻停止播报并开始录音（打断） |

**推荐台词**：`曾侯乙编钟在哪个博物馆？`（对应来源：曾侯乙编钟、湖北省博物馆）

## 四、对比实验（2 分钟，报告加分项）

**操作**：电脑浏览器打开 `http://127.0.0.1:8000/debug` → 工具栏「检索方式」下拉

同一个问题分别用两种模式问，对比**来源**和**答案**：

| 检索方式 | 同一问题：`那把刻着鸟篆的青铜剑是哪朝的` | 现象 |
|---|---|---|
| 关键词 | 命中"越王勾践剑"（字面命中"鸟篆"） | 点名词准，但把"博物馆"三个字也当命中，噪声多 |
| 向量 | 语义召回，来源更相关 | 懂口语化改写，但对阈值敏感 |
| 自动 | 有向量索引时走向量，异常自动降级关键词 | 实际部署用的就是这个 |

**讲解要点**：
- "关键词像查字典，向量像理解意思"；
- 我们做了**混合检索**：向量召回 + BM25 排序 + RRF 融合，再用距离阈值当闸门；
- 阈值是**实测标定**的：正例最高 0.425、闲聊最低 0.440，所以取 0.43。

## 四之二、资料库：不用 AI 也能查（1 分钟）

**操作**：右上角点 📚 按钮

| 演示动作 | 说明 |
|---|---|
| 进入即列出 **615 份**资料 | 博物馆卡 + 文物卡，默认按省份排序，一次 20 条、滚到底自动加载 |
| 输入 `青铜剑` → 搜索 | 命中《越王勾践剑》《湖北省博物馆》等，关键词会记进搜索历史 |
| 类型切换：全部 / 博物馆 / 文物 | 只要某一类 |
| 地区下拉选 `湖北省（19）` | 只看湖北的资料，数字是该条件下的数量 |
| 类别下拉选 `青铜器（47）` | 文物按材质疑聚，可再叠加地区（湖北+青铜器 = 7 条） |
| 点任意一条 | 弹窗显示**资料原文**，可滚动、可复制 |

**讲解要点**：
- 这条路**完全不经过大模型**，不消耗 token，模型不可用时照样能用；
- 三级筛选（类型/地区/类别）的选项与数量由后端 `facets` 动态下发，随关键词变化；
- 它还是"答案有出处"的证据：刚才回答里引用的资料，在这里能翻到原文；
- 工程细节：路径穿越防护（`../` 被挡）、两字短查询、分页、搜索历史本地缓存。

## 四之三、其余体验点（30 秒，顺带展示）

| 功能 | 怎么演示 | 说明 |
|---|---|---|
| **流式输出** | 随便问一句，观察文字是"一个字一个字"冒出来的 | 走 SSE，首字约 0.3 秒出现（原来要等整段生成完） |
| **空态引导** | 冷启动首页有三张"试试这样问我"卡片 | 点一下直接提问，不用现场想问题 |
| **历史对话** | 左上角 ☰ 打开抽屉 → 选一条对话 | 从后端 SQLite 拉回完整多轮对话（含来源） |
| **语音提问** | 点「语音」说一句 | 气泡里会显示识别出的原话，不只是"语音提问"两个字 |

## 五、工程细节（1 分钟，可选，按评委会问什么决定）

| 亮点 | 一句话说明 |
|---|---|
| 双模型兜底 | 文本走 DeepSeek，向量走 SiliconFlow bge-m3；任一不可用会降级而不是挂掉 |
| 增量索引 | manifest 记录每个文件的 sha1，改一份资料只重建那一份（实测 1 秒） |
| 建库速度 | 5122 块、**41 秒**（换 bge-m3 后，比原来 55 分钟快 80 倍） |
| 限流处理 | 向量接口有频率限制，代码里做了批间隔 + 429 指数退避重试 |
| 防幻觉三层 | 检索闸门 → 提示词约束 → 无资料兜底话术 |
| 会话持久化 | SQLite 存历史 + 滚动摘要压缩，长对话不爆上下文 |

## 六、5 分钟精简版流程

1. 开场一句话（20 秒）
2. `越王勾践剑是什么时期的文物？` → 展示来源（40 秒）
3. `它在哪个城市？` → 指代消解（30 秒）
4. `湖北省博物馆开放时间？` → 防幻觉（40 秒）
5. 语音提问一次 + 开关对比一次（60 秒）
6. 调试台切换「关键词 / 向量」对比一次（60 秒）
7. 收尾讲工程亮点（30 秒）

---

## 七、应急预案

| 突发情况 | 处理 |
|---|---|
| 手机连不上后端 | 立刻切到电脑浏览器 `/debug` 继续演示，说明"这是同一套后端接口" |
| 模型超时（偶尔 10 秒+） | 继续讲技术要点，别干等；或换个问题 |
| 语音没声音 | 检查右上角 🔊/🔇 按钮状态 + 手机媒体音量；不行就只演示文字链路 |
| 回答内容不对 | 承认"检索召回不理想"，说明这是已知的阈值/切块权衡（报告"不足与改进"里已写） |
| 完全断网 | 用提前录好的演示视频/截图兜底 |

## 八、演示后可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 为什么不用大模型直接答？ | 会编造（实测编出过不存在的开放时间和展厅名），RAG 让答案有出处 |
| 资料从哪来？ | 国家文物局年度报告 + 各馆公开页面，整理成 Markdown，一物一文件 |
| 资料量大怎么办？ | 分块（600 字）+ 向量索引；当前 616 份、5122 块，检索几十毫秒 |
| 为什么有 616 份而不是全部 7188 家？ | 课程作业按"一级博物馆 + 名品文物"精选，全量会带来 9 万个块、检索噪声和成本 |
| 语音延迟为什么比文字慢？ | 文字生成 1–3 秒，TTS 另需 1–3 秒合成；属已知改进点（可做句子级流水线合成） |
| 有没有做测试 | 后端 158 个单元测试全通过；真机链路（ASR→RAG→TTS）实测通过 |
